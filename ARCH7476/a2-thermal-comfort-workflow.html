Assessment Formats for Residential Thermal Comfort

A room-average study baseline compared with activity-and-clothing profiles at separate locations

1. Decision Recap

Decision

Which format of assessment should be adopted when evaluating thermal comfort in the selected residential case?

Research question: Does evaluating different activity-and-clothing profiles at different locations change comfort-risk identification, scenario rankings or assessment conclusions compared with evaluating room-average conditions for a reference profile? Changed and unchanged conclusions are both valid outcomes.

Alternatives

AssessmentEnvironmental inputsOccupant inputsPurpose
F-Avg: room-average comparison baselineA declared weighted average of local Ta, MRT, RH and air speedReference profile P2Construct a transparent aggregate baseline for this study
F-Sep: separate profiles and locationsThe same local records, retained separatelyEach activity-and-clothing profile at each positionIdentify differences concealed by aggregation

F-Avg is a research baseline, not a claim about the method used by the original architect. Both formats use the same source records and calculation conventions. The profile scenarios are defined by met and clo; they are not validated predictions for named residents, demographic groups or age-related vulnerability.

Audience

Residential design team, comfort consultant and occupants.

Why evidence matters

An aggregate result can hide variation, while a detailed matrix can amplify unsupported assumptions. This study tests both possibilities. A finer format is useful only if the additional information is credible and affects how a comfort finding is interpreted.

What action the evidence should support

Choose whether F-Sep should lead the case assessment, with F-Avg retained as a summary, or whether F-Avg adequately summarises the tested conditions. If case evidence is missing, withhold that recommendation rather than treating missing evidence as support for F-Avg.

Current default scope: begin with a four-profile sensitivity pilot under one explicitly assumed environment. This checks the method only. The full location comparison is conditional on obtaining a named case, credible local inputs and a usable calculation interface. No case-specific result is claimed at this stage.

Assessment indicators

PMV (Predicted Mean Vote) describes a modelled average thermal sensation: negative values indicate cooler sensation and positive values warmer sensation. PPD (Predicted Percentage of Dissatisfied) is derived from PMV and describes predicted dissatisfaction at group level. It is supplementary interpretation, not independent verification or an individual probability. The primary comparison uses PMV direction, range and differences under identical calculation conventions [4].

What is missing from this evidence map

  • A named case, traceable plan and actual activity/location evidence.
  • Local environmental records with time, measurement or model method, and uncertainty.
  • Evidence for spatial or occupancy weights and plausible profile ranges.
  • Completed tool preflight, matched reference calculations and pilot outputs.
  • Occupant feedback for any later comparison with experienced comfort.

Identical inputs assigned to different points cannot demonstrate a spatial effect. Until local evidence is available, the default pilot remains profile sensitivity under an assumed environment. The sample apartment is a method-test layout only; its use cannot support a completed retrospective case claim.

Export is convenient rather than essential: separately entered local conditions and manual records can support the same calculation plan.

  • Likely setup problem: inconsistent unit conversions or corrections between thermBAL and the reference implementation.

Workflow definition

  • Input files: profile definitions and assumed pilot conditions; for the spatial extension, add the named plan, local records, use evidence and uncertainty notes.
  • Variable: F-Avg versus F-Sep. Vary weights, aggregation order and uncertain inputs in separately labelled checks.
  • Steps: preflight → default pilot → spatial-data gate → matched comparison and controls → aggregation and sensitivity checks → recommendation.
  • Expected output: an input audit, comparison matrix, run-count ledger, sensitivity findings and scope-limited conclusion.
  • Likely failure: insufficient spatial data or incompatible calculation conventions.

Profiles and default pilot

P1: seated/resting, 1.0 met and 0.5 clo; P2: seated task, 1.2 met and 0.5 clo; P3: light domestic task, 1.6 met and 0.5 clo; P4: seated task with warmer clothing, 1.2 met and 0.7 clo. P2 is the reference. Relative to P2, P1/P3 vary met while holding clo fixed, and P4 varies clo while holding met fixed. These exploratory values require case support before they represent actual use.

Without local records, run these four profiles under one declared assumed environment. P2 already supplies the reference result, so this is four nominal input sets, not four plus a baseline. Report input-assumption sensitivity only; do not assign identical inputs to three coordinates and count them as spatial evidence.

Spatial extension and calculation ledger

Once the data gate is passed, choose three actually used positions from the plan, potentially window-adjacent, central and deeper in the room. For each documented environmental condition, always complete both diagnostic controls, whether or not the first comparison differs.

Average definition and nonlinearity

F-Avg deliberately averages each of Ta, MRT, RH and air speed before applying the comfort model to P2. This operationalises the proposed input-aggregation baseline; it is not a measured room condition or proof of a physically uniform room. Arithmetic averaging of these variables is a declared simplification. PMV under average inputs need not equal the average of locally calculated PMVs.

Use location weights of 1/3 each only for the exploratory baseline. For sensitivity, compare (0.50, 0.25, 0.25), (0.25, 0.50, 0.25) and (0.25, 0.25, 0.50), in a fixed location order. These are hypothetical weighting tests, not inferred occupancy. Include observed occupancy weights only if supported. Report whether interpretation changes with the weighting choice.

Also compute the weighted mean of the three local P2 PMVs, using the same weights, and report its difference from the PMV calculated after averaging inputs. Treat this as an aggregation-order diagnostic, not a replacement format selected after seeing results. If the conclusion changes with aggregation order, report it as aggregation-sensitive.

Common interpretation and meaningful differences

Report F-Avg as one PMV and F-Sep as all twelve PMVs, their range and the signed difference of each from F-Avg. Interpret all results using the same predeclared screening interval, initially -0.5 to +0.5 inclusive. This remains a threshold-based classification; it is not a claim of standards compliance. Do not assign F-Sep a separate overall pass/fail rule or population coverage rate.

A potential concealed discrepancy occurs when F-Avg lies inside the interval and a local-profile result lies outside. A contrary-direction discrepancy requires one result above +0.5 and the other below -0.5. A sign change within the interval, such as +0.05 to -0.05, does not count. Keep continuous values visible alongside classifications.

For each potential discrepancy, record the input source, whether the activity/location is documented or hypothetical, the affected interpretation and its sensitivity. A case-specific recommendation requires documented use and credible inputs. Hypothetical profiles can demonstrate methodological sensitivity, but cannot justify a claim about actual residents. Missing evidence means the case decision is unresolved; it is not a negative result favouring F-Avg.

Diagnostic controls and reference verification

Always use P2 at all locations to examine location effects, and all profiles under the average environment to examine profile-assumption effects. Reuse the ledger results. Together with F-Sep, these controls explain combined effects; they do not establish that a more detailed format is preferable.

Before case comparison, cross-check P2 under representative conditions and a lower/higher met or clo input against a documented reference implementation. Record all six inputs, units, software version/date, corrections, calculation mode and signed PMV differences. Align raw PMV with raw PMV; assess elevated-air-speed corrections separately. Resolve incompatible conventions before interpreting differences.

No universal PMV pass tolerance is adopted because a validated error bound has not been established. Record the largest observed absolute difference among matched checks as a provisional numerical sensitivity margin, not a statistical confidence interval or proof of accuracy. Flag any result whose distance from -0.5 or +0.5 is no larger than this margin. If adding/subtracting that margin changes its classification, withhold a firm inside/outside conclusion. Large unexplained discrepancies suspend interpretation.

Sensitivity and repeated conditions

Test source-supported ranges for environmental inputs and met/clo, plus the declared weighting and aggregation-order checks. If uncertainty is not known, label perturbations exploratory and do not claim robustness for the case. Use the same interval throughout the main comparison; a separately labelled threshold check may use ±0.4 and ±0.6 for both formats.

If three documented conditions become available, present a condition-by-condition table. Define a supported finding as a discrepancy with credible inputs and documented use that retains its interpretation under the declared checks. Report k/n supported findings, using only fully assessable conditions in n; also report the planned total and exclusions. Use 'recurring' only for a finding present in at least two conditions, and distinguish recurrence of the same combination from different combinations. Do not treat conditions as random statistical replicates.

A single supported finding in an important occupied condition can justify F-Sep for that condition; a majority is not required. Recommend wider adoption only over the conditions supported by the evidence. Report no added value demonstrated, within scope, only when all planned relevant conditions have adequate evidence and no supported discrepancy occurs. Otherwise leave the broader decision unresolved. Scenario rankings remain optional and require a separately declared common objective before analysis.

5. A4 Branch Declaration

Route

The course offers Route A (Retrospective Redesign) and Route B (Live Studio Application) [1]. I provisionally select Route A for an existing residential case. These course branches are distinct from F-Avg and F-Sep.

Route A becomes a completed case study only after a real case, plan, use context and relevant inputs are secured. If only the bundled apartment remains available, submit the work as an exploratory method prototype and flag the retrospective branch as unfulfilled, subject to tutor agreement. Do not relabel it Route B without an actual live studio application. F-Avg remains a study-constructed baseline; historical claims about the original evaluation require separate evidence.

Decision

  • Project: residential thermal-comfort assessment, with the specific case pending.
  • Decision: which assessment format should be adopted.
  • Alternatives: F-Avg, an aggregate reference-profile baseline; F-Sep, separate activity/clothing profiles and positions.
  • Why this matters: input aggregation can conceal differences, while unsupported detail can mislead. The report must distinguish both possibilities.

Workflow

  • Primary route: Preset simulation / thermBAL, with spreadsheet post-processing; provisionally selected pending preflight.
  • Inputs: declared profiles and pilot environment; add case/local/use data for the spatial extension.
  • What varies: reporting format, with weights and aggregation order checked separately.
  • Minimum scope: four nominal profile-only sets by default. After the spatial-data gate, sixteen nominal sets per condition, including all controls; three conditions require 48 before deduplication. Verification and sensitivities are extra.
  • Output: comparison matrix, calculation ledger, diagnostic findings and a scope-limited recommendation.
  • Comparison rule: apply one PMV interval to both formats, flag numerical and input uncertainty, and require documented relevance before a case-specific recommendation.

Feasibility

  • By A3: a recorded preflight, four-profile pilot and matched reference check. The full decision additionally needs a named case and local data.
  • Likely failure: local environmental or use evidence remains unavailable.
  • Backup route: manual entry and recording of supported conditions; if calculation controls are inadequate, use a documented Python calculator and reverify.
  • Simplification: retain the profile-only prototype and leave the spatial adoption decision open; defer repeated conditions and rankings.

Branch Statement

I plan to use Route A to compare F-Avg and F-Sep in a documented residential case, using the same input records and comfort-model conventions. Until that evidence is available, I will test activity-and-clothing assumptions in an exploratory pilot. The purpose is to determine whether separate profiles and locations add credible information to the aggregate baseline, not to presume a better format or attribute a method to the original architect. The final recommendation will state its evidence, uncertainty and applicable conditions.
